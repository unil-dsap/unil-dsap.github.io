Warm-up 1

Calls inside calls are read from the inside out. Two ways to round a fee to cents. What does the program print?

fee = -2.675
print(round(abs(fee), 2), round(abs(fee) * 100) / 100)
  1. 2.68 2.68
  2. 2.67 2.68
  3. 2.67 2.67
  4. -2.67 -2.68
Show the answer

2.67 2.68

Inside out. abs gives 2.675, which is stored slightly below 2.675, so round(..., 2) gives 2.67. But 2.675 * 100 comes out as exactly 267.5, round gives 268, and 268 / 100 is 2.68. Same fee, two answers: session 2's floats again.

Warm-up 3

The same function, called with keywords. What does the program print?

def value(shares, price):
    return shares * price

print(value(price=190.5, shares=10), value(190.5, 10))
  1. 1905.0 1905.0
  2. TypeError on line 4
  3. 1905.0 TypeError
  4. 1905.0 19.05
Show the answer

1905.0 1905.0

Keywords are matched by name, so their order does not matter. The second call swaps the positions, and here it still prints 1905.0 only because multiplication does not care. With a division it would lie.

  2. Task 1: None None
  3. Task 1: 409.2 409.2
  4. Task 1: None 409.2
Show the answer

Task 1: None 409.2

value_p SHOWS 409.2 on the screen while it runs, then gives back nothing: every function without return returns None, so a is None. value_r shows nothing and hands 409.2 back to the program. A value on the screen is not a value in a variable (session 1's round, again).

Task 2 · two variables called total

Predict the print. Then explain: the function assigns to total. Why is the total outside still 100.0?

total = 100.0

def add_fee(amount):
    total = amount + 2.5
    return total

x = add_fee(40.0)
print(x, total)

What does the print show?

  1. 42.5 42.5
  2. 102.5 100.0
  3. 42.5 100.0
  4. NameError
Show the answer

42.5 100.0

Assigning inside a function creates a LOCAL name. The total inside add_fee is a different variable that happens to share the name; it disappears when the call ends. The only way out of a function is return.

Task 3 · what the function changed

Two functions, each changes its parameter. Predict both prints. Why does the list outside change, and the number outside not?

def add_position(shares, n):
    shares.append(n)
    return len(shares)

def add_one(n):
    n = n + 1
    return n

shares = [10, 4, 2]
k = add_position(shares, 7)
print(k, shares)

m = 5
y = add_one(m)
print(m, y)

What does Task 3a print?

  1. None [10, 4, 2, 7]
  2. 3 [10, 4, 2]
  3. 4 [10, 4, 2, 7]
  4. 4 [10, 4, 2]
Show the answer

4 [10, 4, 2, 7]

Inside add_position, shares is a second name for the caller's list (session 3: two names, one list), and append changes that list in place. In add_one, n = n + 1 builds a NEW number and moves the local label n to it; the caller's 5 cannot change, because ints are immutable. Lists are mutable.

Task 4 · which methods change the value?

One string method chain, one list method. Predict all four printed values. Which method changed its object, and which returned a new one?

ticker = " nesn "
t2 = ticker.strip().upper()
shares = [10, 4, 2]
s2 = shares.sort()
print(repr(ticker), t2, shares, s2)

What does the print show?

  1. 'NESN' NESN [2, 4, 10] [2, 4, 10]
  2. 'NESN' NESN [2, 4, 10] None
  3. ' nesn ' NESN [2, 4, 10] None
  4. ' nesn ' NESN [10, 4, 2] [2, 4, 10]
Show the answer

' nesn ' NESN [2, 4, 10] None

Strings never change: .strip() and .upper() each return a NEW string, and ticker keeps its spaces. .sort() changes the list itself and returns None, so s2 is None. That is why shares = shares.sort() destroys a list. repr() shows the quotes, so the spaces become visible.

Task 5 · the weight that lies

AAPL is worth 1905.0 of a 3338.2 CHF ledger. The function below computes its weight in percent. The call runs and prints a number. Is it right? Find the mistake and fix it so that no one can make it again.

def weight(value, total):
    return value / total * 100

print(f"{weight(3338.2, 1905.0):.1f}%")

What does the buggy call print?

  1. TypeError
  2. 1.8%
  3. 57.1%
  4. 175.2%
Show the answer

175.2%

The buggy call prints 175.2%: arguments are matched by POSITION, so value got the total and total got the value. No error, because dividing two numbers always works. Rough check: one position cannot be 175 % of the ledger. Keyword arguments (value=..., total=...) make the order impossible to get wrong.
