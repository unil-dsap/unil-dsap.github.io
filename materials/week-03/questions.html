Warm-up 1

price = "190.5"      # read from a file

  2. TypeError on line 3

190.5190.5190.5

int times str is allowed: it repeats the text. No error, wrong number: runs and lies.

Warm-up 4

Prices read from a file are still text. What do max() and sorted() give?

Warm-up 5

Warm-up 7

Each price gets a label with if / elif / else. What is in the list at the end?

labels = []

The first true condition wins. 150 > 100 is already true, so the elif is never checked. Put the stricter test first.

Warm-up 9

We loop over the holdings and keep the tickers with at least 4 shares. What does the program print?

holdings = {"AAPL": 10, "NESN": 4, "VOO": 2}
big = []
for ticker, n in holdings.items():
    if n >= 4:
        big.append(ticker)
print(big, len(holdings))
  1. ['AAPL', 'NESN'] 3
  2. ['AAPL', 'NESN'] 16
  3. ['AAPL'] 3
  4. [10, 4] 3
Show the answer

['AAPL', 'NESN'] 3

.items() gives (key, value) pairs. >= 4 includes 4. len() of a dict counts the keys.

Warm-up 10

We look up a ticker with .get() and test two things with in. What does the program print?

holdings = {"AAPL": 10, "NESN": 5}
print(holdings.get("aapl"), "NESN" in holdings, 5 in holdings)
  1. None True False
  2. None True True
  3. KeyError on line 2
  4. 10 True True

Keys are case-sensitive; .get() gives None for a missing key. 'in' looks at the keys, never at the values.

Warm-up 11

1000 CHF grows by 5 % a year until it is at least 1100. What does the program print?

cash = 1000
years = 0
while cash < 1100:
    cash = cash * 1.05
    years += 1
print(years, round(cash, 2))
  1. 2 1102.5
  2. 3 1157.63
  3. 2 1100.0
  4. 1 1050.0
Show the answer

2 1102.5

After one year 1050 < 1100, so the loop runs again. It stops at the first value that is NOT below 1100.

Reading tasks

Every task starts from this ledger:

tickers = ["AAPL", "NESN", "VOO"]
shares = [10, 4, 2]
price = {"AAPL": 190.5, "NESN": 102.3, "VOO": 512.0}
closes = [190.5, 187.2, 193.8, 185.1, 191.4, 198.6, 194.0]   # AAPL, day 0 to day 6

Task 1 · slices

On paper, predict what each line prints. Then run and compare. Remember: positions start at 0, the stop is not included, and a slice never crashes.

print(closes[1:4])
print(closes[::3])
print(closes[::-1][:2])
print(closes[5:100])
print(tickers[3:])

What is closes[::-1][:2]?

  1. [190.5, 187.2]
  2. [187.2, 190.5]
  3. [198.6, 194.0]
  4. [194.0, 198.6]
Show the answer

[194.0, 198.6]

[1:4] is positions 1, 2, 3. [::3] takes every third item from the start. [::-1] reverses, then [:2] keeps the first two of the reversed list: the last two days, newest first. [5:100] stops at the end instead of crashing. tickers[3:] is empty, while tickers[3] would be an IndexError.

Task 2 · a copy, or a second name?

Predict both lines. Then say in one sentence what backup = shares creates, and what shares.copy() creates.

backup = shares
backup.append(5)
print(shares)

shares = [10, 4, 2]
backup = shares.copy()
backup[1] = 10
print(shares, backup)

What does Task 2a print?

  1. [10, 4, 2]
  2. [5]
  3. an error
  4. [10, 4, 2, 5]
Show the answer

[10, 4, 2, 5]

backup = shares puts a second name on the SAME list, so append through one name shows through the other. shares.copy() builds a NEW list; changing the copy leaves the original alone. Numbers and text never surprise you like this, because they cannot change; lists and dicts can.

Task 3 · the zip that lies

The total of the ledger is 3338.2. Someone wanted the positions "in order" and put sorted(shares) inside the zip. It runs, and prints a total that looks like money. First fill in an iteration table ON PAPER (ticker, shares, value, running total), then explain what went wrong and fix it.

total = 0.0
for t, n in zip(tickers, sorted(shares)):
    total += n * price[t]
print(total)

What total does the buggy loop print?

  1. 3338.2
  2. 1024.0
  3. 5910.2
  4. 8048.0
Show the answer

5910.2

The buggy version prints 5910.2. sorted(shares) is [2, 4, 10], and zip pairs by position, so AAPL gets 2 shares and VOO gets 10. Two lists that describe the same rows must stay in the same order. Rough check: VOO alone (5120.0) cannot be worth more than the whole ledger.

Task 4 · the boundary

The broker's rule: "positions of 1000 CHF or more pay a 0.1 % fee". A position of 8 shares at 125.00 is exactly 1000.00 CHF. The code says it pays nothing. Who is right? Fix the code.

value = 8 * 125.0
if value > 1000:
    fee = value * 0.001
else:
    fee = 0.0
print(value, fee)

What should the fee be for exactly 1000.00 CHF?

  1. 0.0
  2. 0.1
  3. 10.0
  4. 1.0
Show the answer

1.0

"Or more" means >=. With > the boundary case pays nothing: no error, a wrong number, and only one value in the whole world triggers it. The code does not decide which is right; the rule written down does.
